## 1. 这个插件解决什么问题

大模型只能读写文件、调用 API，**看不见屏幕、也点不了鼠标**。但很多事只有界面上才能做：微信里的一个链接、一个只有图形界面的答题页、一个必须点"下一步"的安装向导。

本插件把 Windows 桌面变成智能体可调用的 9 个工具：

| 能力 | 工具 | 说明 |
| --- | --- | --- |
| 看 | `desktop_screenshot`、`desktop_ocr`、`desktop_uia` | 截图、识别文字、读取控件树 |
| 动 | `desktop_mouse`、`desktop_keyboard` | 点击、拖拽、滚轮、输入、快捷键 |
| 管 | `desktop_window`、`desktop_wait` | 找窗口、切前台、等界面出现 |
| 搬 | `desktop_clipboard` | 把界面里的文字取出/放进去 |

**能做的**：读屏幕、点按钮、填表单、翻页、切窗口、从界面里抄数据。
**不能做的**：绕过登录、破解验证码、操作锁屏或 UAC 安全桌面、在没有图形界面的环境里工作。

## 2. 安装与验证

### 2.1 前置条件

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11（x64 或 arm64） |
| DSH | 0.2.2-rc.5 及以上、0.4.0 以下；Desktop 版或 CLI 版均可 |
| PowerShell | `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`（系统自带） |
| OCR 语言 | 系统设置 → 时间和语言 → 语言，至少装一个含"光学字符识别"的语言包；中文系统通常自带 |

用 `desktop_status` 可以一次确认以上三项（见 2.4）。

### 2.2 安装

**方式一：插件面板（推荐给普通用户）**

1. 打开 DSH → **插件**（Plugins）→ **添加插件**（Add plugin）
2. 选择本仓库目录（包含 `package.json` 的那一层）
3. 安装完成后确认列表中出现 **桌面操控 / Desktop control**，状态为启用

**方式二：让智能体安装**

把仓库目录的绝对路径告诉智能体，它会调用 `plugin_manager`：

```
把 D:\dsh_workspace\开发\电脑桌面控制插件 安装成插件
```

执行的动作等价于：

```json
{ "action": "install_bundle", "target": "D:\\dsh_workspace\\开发\\电脑桌面控制插件" }
```

安装器会把它链接进当前 profile（`$DSH_HOME/profiles/<profile>/node_modules`），并在 `cordis.patch.yml` 里写入插件行。

**方式三：手工挂载（高级）**

在 profile 的 `cordis.patch.yml` 末尾追加：

```yaml
- insert:
    - id: dsh-plugin-desktop-control
      name: 'dsh-plugin-desktop-control'
      config:
        idleMinutes: 120
        ocrScale: 2
```

并在 profile 的 `package.json` 的 `dsh.profile.bundles` 中加入 `dsh-plugin-desktop-control`。

### 2.3 版本配置说明

`package.json` 里已声明：

```json
"engines": { "dsh": ">=0.2.2-rc.5 <0.4.0-0" }
```

- 低于 `0.2.2-rc.5`：工具注册接口（`ctx.tools.register` 要求 `output.schema` + `render`）不匹配，插件会被安全地拒绝加载。
- 高于等于 `0.4.0`：未验证，安装器会要求显式豁免才允许强行启用。**不建议**在未验证的版本上豁免使用。

插件本身没有 npm 运行时依赖，`package.json` 不声明 `dependencies`，因此安装不联网、不执行构建脚本。

### 2.4 验证安装

新开一个会话，对智能体说：

```
用 desktop_status 看一下这台机器
```

预期输出类似：

```
Desktop agent 1.0.0 (pid 14128)
Screen: screen 2560x1440 at origin 0,0 physical pixels
OCR: available [en-US, zh-Hans-CN]
UI Automation: available
Foreground: "微信" [Weixin] handle=2622440 352x476 at 1104,453
Cursor: 602,601
Agent process: running, idle timeout 120 min
```

要点：
- `screen` 显示的是**物理像素**，不是 1080p 之类的逻辑分辨率。2560x1440 且系统缩放 125% 是正常现象。
- `OCR: available` 且语言列表非空，说明 OCR 可用。
- `Agent process: running` 表示常驻代理已启动（首次调用会慢 1~2 秒）。

### 2.5 卸载

插件面板里删除，或让智能体执行 `plugin_manager` 的 `remove_bundle`。代理进程会随插件卸载被回收；即使残留，也会在 `idleMinutes` 后自行退出。

## 3. 五分钟上手

**① 让智能体打开记事本并写字**

```
打开记事本，输入"Hello 桌面操控 2026"，然后截图给我看看
```

**② 让它读当前屏幕**

```
截个图，告诉我屏幕上都有哪些窗口，分别是什么
```

**③ 让它操作浏览器**

```
用浏览器打开 https://example.com ，把页面标题读给我
```

四步走是固定的：**看清楚 → 找位置 → 做动作 → 再确认**。插件不替代这个循环，只是把这个循环变得可以调用。

## 4. 必须先懂的四个概念

### 4.1 物理像素

所有工具的坐标都是**物理像素**，原点在虚拟桌面左上角（单显示器时就是主屏左上角）。

Windows 在高 DPI 屏幕上会向"不感知 DPI"的程序虚报一个更小的分辨率。本插件的代理进程显式声明了 Per-Monitor DPI 感知，所以：

- 125% 缩放的 2560x1440 屏幕，在工具眼里就是 2560x1440，**不是 2048x1152**。
- `desktop_screenshot` 存下来的 PNG 尺寸 = 物理像素尺寸，图上的像素坐标可以直接当点击坐标用。
- 如果你用别的工具（画图、QQ 截图）量到的是逻辑坐标，需要乘以缩放比才能喂给本插件。

判断当前缩放：`desktop_status` 的 `screen` 与 `显示器设置` 里的"分辨率"对比即可。

### 4.2 前台窗口

Windows 只会把**键盘输入**送给前台窗口；鼠标点击虽然能落在任意窗口上，但**第一次点击通常只起到"激活"的作用**，不会传给窗口里的控件。

所以标准动作是：

1. `desktop_window activate`（确认返回里有 `foreground`）
2. 再 `desktop_mouse click`

如果点击后界面没反应，先看 `desktop_status` 的 `Foreground` 是不是目标窗口，然后**再点一次**。

### 4.3 感知顺序：先看，再点

插件提供三种"看"的方式，优先级从高到低：

| 方式 | 何时用 | 代价 |
| --- | --- | --- |
| 截图 + 视觉 | 布局复杂、有图标/颜色/选中态、OCR 认不准 | 一张 PNG，模型直接看图 |
| `desktop_ocr` | 纯文本界面、需要精确坐标、要程序化匹配 | 80~500ms |
| `desktop_uia` | 传统 Win32 / 微信这类暴露无障碍的程序 | 快且精确，但很多程序不支持 |

实践建议：**先 `desktop_screenshot` 存图，再用 `read_image` 看一眼**确认界面状态；需要坐标时用 `desktop_ocr`；对微信这类支持 UI Automation 的程序优先 `find` + `invoke`。

> Edge / Chrome 的网页内容**不会**通过 UI Automation 暴露控件（只暴露浏览器外壳），网页一律用截图 + OCR/视觉。

### 4.4 常驻代理进程

插件本身不直接操作桌面，而是启动一个常驻的 Windows PowerShell 进程（"代理"）：

- 第一次调用某个工具时启动，约 1~2 秒
- 之后每次调用只走本机 TCP，几十毫秒
- 空闲 `idleMinutes`（默认 120 分钟）后自动退出，下次调用再启动
- 单次请求超时（默认 45 秒）会被判定为卡死，代理被强制结束，下次调用自动重建

代理日志：`%TEMP%\dsh-desktop-control\agent.log`
截图目录：`%TEMP%\dsh-desktop-control\shots\`

## 5. 工具参考

下面每个工具都给出：用途、参数、返回、注意事项。

### 5.1 `desktop_status`

查看代理和环境状态。**每次接手桌面任务前先调一次**，确认屏幕尺寸、前台窗口、OCR 可用。

参数：无。

返回（渲染后的文本）包含：代理版本与 pid、`screen`（物理像素）、`OCR` 语言列表、`UI Automation` 可用性、`Foreground`（标题/进程/handle/矩形）、`Cursor`、代理是否在运行、空闲超时。

### 5.2 `desktop_screenshot`

把屏幕、某个窗口或某个矩形存成 PNG，可选同时 OCR。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `mode` | `full` / `window` / `region` | 默认 `full`（整个虚拟桌面） |
| `handle` | 整数 | `mode=window` 时的窗口句柄 |
| `title` | 字符串 | 用标题/片段代替 handle，内部自动查找 |
| `region` | `{x,y,width,height}` | `mode=region` 的矩形，物理像素 |
| `scale` | 数字 | 存档放大倍数，默认 1；小字界面可用 2 |
| `ocr` | 布尔 | 同一次调用顺带 OCR，返回文字与坐标 |
| `path` | 字符串 | 指定输出 PNG；相对路径落在截图目录 |

返回：PNG 路径、宽高、起点 `origin`、字节数；`ocr=true` 时附 OCR 行。

**注意**：
- 截窗口时若窗口被遮挡，截到的是**遮挡物**，不是窗口本身——先 `activate`。
- 截图只包含屏幕可见区域；窗口超出屏幕的部分会被裁掉，`origin` 就是裁剪后的起点。

### 5.3 `desktop_ocr`

用系统自带的 OCR 引擎识别文字。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `image` | 字符串 | 直接识别已有 PNG（可传绝对路径或截图目录内的相对名） |
| `mode` / `handle` / `title` / `region` | | 不传 `image` 时，实时截取后识别 |
| `scale` | 数字 | 识别前放大倍数，默认 2；小字建议 3~4 |
| `lang` | 字符串 | `zh-Hans-CN` / `en-US`，默认跟随系统 |
| `words` | 布尔 | 附带每个词的框，用于更细的定位 |

返回每行：

```
L3 x=650 y=554 w=527 h=32 c=914,570 | 点击开始答题： 2026 年安全知识测验
```

`c=cx,cy` 是可直接点击的中心点。中文之间的空格已做归一化，英文单词间隔保留。

**注意**：OCR 会漏字（尤其小字号、浅色字、带背景图的字）。关键判断不要只依赖 OCR——看一眼截图更稳。

### 5.4 `desktop_mouse`

| 参数 | 说明 |
| --- | --- |
| `action` | `click`（默认）/ `double_click` / `right_click` / `middle_click` / `move` / `scroll` / `drag` / `down` / `up` |
| `x`,`y` | 目标点，物理像素（必填） |
| `toX`,`toY` | `drag` 的终点 |
| `amount` | 滚轮格数，正数向上，默认 3 |
| `horizontal` | 横向滚动 |

返回：动作、坐标、光标最终位置、**点击点下面的窗口**（标题/进程/类名）——用它可以判断"我点到的是不是我想要的窗口"。

### 5.5 `desktop_keyboard`

| 参数 | 说明 |
| --- | --- |
| `action` | `type`（默认）/ `press` / `hotkey` |
| `text` | `type` 的文本，任意 Unicode（含中文、emoji） |
| `keys` | `press`/`hotkey` 的按键，如 `enter`、`tab`、`esc`、`ctrl+a`、`alt+F4`、`win` |
| `method` | `auto`（默认，走剪贴板粘贴）/ `keys`（虚拟键码，仅 ASCII）/ `paste` / `unicode`（SendInput） |
| `holdMs` | 组合键按住时长，默认 40ms |

**为什么默认走剪贴板**：中文输入法激活时，直接发键码会被输入法当成拼音组合（`dca-ok` 变成 `dca—ok`）。粘贴不受输入法影响，且中英文一致。粘贴前后会保存/恢复剪贴板内容（文本或图片）。

`keys` 适合密码框、禁用粘贴的输入框等场景，但只支持可见 ASCII 字符。

### 5.6 `desktop_window`

| `action` | 说明 |
| --- | --- |
| `list` | 列出可见顶层窗口（handle、标题、进程、矩形、最小化/最大化、是否前台） |
| `find` | 按 `title` / `process` 找窗口，返回单个结果 |
| `activate` | 切到前台（返回 `activated` 与 `foreground`） |
| `minimize` / `maximize` / `restore` / `close` / `move` | 常规窗口操作 |
| `launch` | 启动程序、打开文档或 URL（`command` + `args` + `cwd`），并等待新窗口出现 |

标题匹配顺序：完全相等 → 忽略大小写包含 → 正则。

**注意**：
- `activate` 返回 `foreground=false` 表示没抢到前台（常见于系统弹层、UAC、锁屏）。此时点击和输入都不会进目标窗口。
- `launch` 传 `https://...` 会用默认浏览器打开；传本地 `.html`/`.txt` 会用关联程序打开。

### 5.7 `desktop_uia`

| `action` | 说明 |
| --- | --- |
| `tree` | 打印控件树（`depth` 默认 6，`maxNodes` 默认 400），每个节点带 `path` |
| `find` | 按 `name`（包含匹配）/ `controlType` 查找，返回 `path` 与中心点 |
| `invoke` | 按 `path` 触发控件（优先 InvokePattern，不行则模拟点击中心） |
| `set_value` | 给输入框赋值（ValuePattern） |
| `focus` | 聚焦控件 |
| `text` | 读取控件文本（TextPattern） |

**注意**：
- `controlType` 只是提示。有些程序（走 MSAA 桥）把所有控件都报成 `Pane`，插件会自动退化为只按名字匹配，并在结果里标注"type filter was ignored"。
- 只对暴露无障碍的程序有效。微信 4.x、传统 Win32 程序通常可以；Electron/网页内容通常不行。

### 5.8 `desktop_clipboard`

`action: get` 读取文本；`action: set` 写入文本（写入后会回读校验）。

用途：把界面里的长文本"复制"出来（先 `hotkey ctrl+c` 再 `get`），或者把长文本"粘贴"进去（`set` 之后 `hotkey ctrl+v`）。

### 5.9 `desktop_wait`

| 参数 | 说明 |
| --- | --- |
| `kind` | `window`（默认，轮询窗口标题）/ `text`（轮询 OCR 文字） |
| `pattern` | 子串或正则 |
| `handle` / `title` | `kind=text` 时限定某个窗口 |
| `region` | `kind=text` 时限定矩形 |
| `timeoutMs` | 最长等待，默认 10000 |
| `intervalMs` | 轮询间隔，默认 400（最小 150） |

返回 `matched`、`elapsedMs`，命中时附窗口信息或命中的那一行文字。

比"固定 sleep 两秒"可靠得多：界面先出来就立刻继续，没出来就等到超时。

## 6. 实战配方

### 6.1 微信：读消息 → 点链接 → 答题（核心场景）

> 目标：微信里某人发来一个答题链接，让智能体点进去答题并把结果告诉你。

**第 0 步：确认微信状态**

```
desktop_window find  title=微信  process=Weixin
```

- 没有窗口：`desktop_window launch command=D:\wechat\Weixin\Weixin.exe`（按实际安装路径）
- 出现"微信 / 头像 / 进入微信"的小窗（约 352x476）：**说明未登录**。此时不要点"进入微信"，直接告诉用户"微信未登录，需要先扫码/点击登录"。
- 出现主窗口（通常 1000x700 以上）：继续。

**第 1 步：切到前台并截图**

```
desktop_window activate  handle=<微信 handle>
desktop_screenshot       mode=full
```

看图（`read_image`）确认左侧会话列表里有没有目标联系人。

**第 2 步：找到并点开会话**

两种方式，优先第二种：

- 视觉：在截图上找到"郭梦龙"那一行的位置，`desktop_mouse click` 该点。
- 搜索：`desktop_keyboard hotkey ctrl+f` → `desktop_keyboard type 郭梦龙` → `desktop_wait text 郭梦龙` → 点第一条结果 → `esc` 退出搜索。

**第 3 步：找到链接**

```
desktop_screenshot   mode=region  region={x,y,w,h}   # 聊天内容区
```

链接一般是蓝色/下划线文字，OCR 能读出形如 `https://...` 或"点击...""答题"等文案。点它的中心点。

**第 4 步：等页面打开**

```
desktop_wait kind=window pattern=答题        # 标题里通常带关键词
desktop_window list                           # 或者看有没有新的浏览器/内置浏览器窗口
```

微信内置浏览器的窗口标题通常就是网页标题；也可能用系统默认浏览器打开。

**第 5 步：答题**

1. `desktop_screenshot mode=window handle=<页面窗口>` + `read_image` 读题
2. 题目多时用 `desktop_mouse scroll` 往下翻，再截图
3. 每题点选项，点完**截图确认单选点变实心**
4. 全部答完点"提交"

**第 6 步：读回结果**

```
desktop_wait kind=text pattern=得分
desktop_screenshot mode=window handle=<页面窗口>
```

读取得分，和题目数核对（例如 6 题答对 6 题就是 6/6）。

**第 7 步：汇报并收尾**

- 关掉答题窗口（只关自己打开的）
- 切回微信主窗口但不做任何输入
- 明确告诉用户"没有给对方发消息"

> ⚠️ **安全红线**：整个过程中，微信聊天输入框一旦获得焦点，任何误触的回车/字符都会变成一条发出的消息。答题期间不要激活微信窗口；不要用 `desktop_keyboard type` 在微信里输入任何内容（除非用户明确要求发消息）。

### 6.2 网页表单填写

1. `desktop_window launch command=<url>` 或点页面上的链接
2. `desktop_window activate` 目标浏览器
3. 点第一个输入框 → `desktop_keyboard type` → `desktop_keyboard press tab` 逐项填
4. 每个字段填完截图确认
5. 点提交前**再确认一次**所有字段内容（截图 + 读图）

### 6.3 从桌面应用里取数据

比 OCR 更可靠的办法是"复制"：

1. 激活应用，点中要复制的区域（或 `hotkey ctrl+a`）
2. `desktop_keyboard hotkey ctrl+c`
3. `desktop_clipboard action=get`

适用于：聊天记录、表格、日志窗口、错误弹窗文本。

### 6.4 等待与重试

固定 `sleep` 是脆弱来源。推荐：

```
desktop_wait kind=window pattern=加载完成      timeoutMs=15000
desktop_wait kind=text   pattern=提交成功      timeoutMs=15000
```

超时后再截图看实际状态，而不是盲目重复点击。

## 8. 配置项

在 `cordis.patch.yml` 的插件行里配置：

```yaml
- id: dsh-plugin-desktop-control
  name: 'dsh-plugin-desktop-control'
  config:
    idleMinutes: 120
    ocrScale: 2
    screenshotDir: ''
    requestTimeoutMs: 45000
    powershell: ''
    logDir: ''
```

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `idleMinutes` | `120` | 代理空闲多少分钟后退出。调大更省启动时间，调小更省内存 |
| `ocrScale` | `2` | OCR 前的放大倍数。小字界面可调 3~4，大字号可调 1 提速 |
| `screenshotDir` | 空 | 截图目录；空表示 `%TEMP%\dsh-desktop-control\shots` |
| `requestTimeoutMs` | `45000` | 单次请求超时；超时会杀掉代理并自动重建 |
| `powershell` | 空 | 指定其它 PowerShell 可执行文件（例如 PowerShell 7 的 `pwsh.exe` —— 未验证，建议保持默认 5.1） |
| `logDir` | 空 | 代理日志与就绪文件目录；空表示 `%TEMP%\dsh-desktop-control` |

修改后需要重载插件（禁用再启用，或重启 DSH）才生效。

## 10. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 调用工具报 `the desktop agent did not report a port in time` | PowerShell 启动失败、被杀软拦截、路径不对 | 看 `%TEMP%\dsh-desktop-control\agent.log`；配置 `powershell` 指向真实路径；把插件目录加入杀软白名单 |
| 报 `did not answer "xxx" within 45000 ms` | 目标程序 UI 线程卡死（激活/点击时同步等待） | 已自动杀掉代理，直接重试；若反复出现，改用 UIA 或键盘操作 |
| 点击没反应 | 目标窗口不在前台；第一次点击只起激活作用；点被遮挡 | `desktop_window activate` 后**再点一次**；用 `desktop_status` 确认 Foreground；截图确认坐标 |
| 键盘输入没进去 | 焦点不在输入框；中文输入法把键码当成拼音 | 先点一下输入框；`type` 用默认的粘贴方式；必要时 `method=keys` 只输 ASCII |
| OCR 漏字 / 乱码 | 字号太小、对比度低、背景花 | `scale` 提到 3~4；只截目标区域；改用截图 + 视觉读图 |
| 坐标整体偏移 | 用了逻辑坐标而不是物理像素 | 以 `desktop_status` 的 `screen` 为准；截图 PNG 的像素坐标就是物理坐标 |
| `activate` 一直返回 `foreground=false` | 系统弹层（搜索/开始菜单/UAC）占着前台 | 先 `desktop_keyboard press esc` 关掉弹层；UAC 安全桌面下无法自动操作，需要人工确认 |
| `desktop_uia` 返回 0 匹配 | 该程序不暴露无障碍（网页内容、自绘界面） | 改用截图 + OCR/视觉 |
| 微信窗口只有 "进入微信" 按钮 | 微信未登录 | 让用户先登录；插件不会代为登录 |
| 点击位置对但界面不变 | 该控件不响应鼠标（少见），或程序把点击当成"激活" | 试 `desktop_uia invoke`（微信 4.x 支持） |
| 鼠标光标自己乱跑 | 有远程控制软件（如向日葵、ToDesk）在被控端注入鼠标位置 | 关闭远程会话，或用键盘操作；`desktop_status` 的 `Cursor` 与你设置的点不一致即为该情况 |
| 屏幕全黑 | 桌面锁定 / 显示器休眠 / 安全桌面 | 先解锁；本插件不处理锁屏 |

排错三件套：

1. `desktop_status` —— 看前台窗口、光标、代理是否正常
2. `desktop_screenshot mode=full` + `read_image` —— 看真实界面
3. `%TEMP%\dsh-desktop-control\agent.log` —— 看每个请求的成功/失败与耗时

## 11. 安全与合规

- **插件不做二次确认**。`desktop_mouse` 点下去就是点下去：可能触发发送消息、提交表单、删除数据、付款。
- 给智能体的指令要写清"能做什么、不能做什么"。涉及聊天工具时，明确写"不要发送消息"。
- 不要在无人看管的情况下让它操作涉及资金的界面。
- 截图可能包含隐私信息（聊天记录、密码框）。截图默认落在 `%TEMP%`，定期清理；也可以用 `screenshotDir` 指到受控目录。
- 剪贴板会被短暂占用（粘贴输入时会写入并立刻还原）。不要在粘贴瞬间复制别的东西。
- 插件不联网、不上传任何屏幕内容；所有识别都在本机完成。

## 14. 附录：代理协议与日志

代理是标准输入输出之外的独立进程，通过 `127.0.0.1` 随机端口的 TCP 通信，一行一个 JSON：

请求：

```json
{ "id": "12", "token": "<随机>", "cmd": "mouse", "req": { "action": "click", "x": 640, "y": 360 } }
```

成功响应：

```json
{ "id": "12", "ok": true, "result": { "action": "click", "x": 640, "y": 360, "cursor": { "x": 640, "y": 360 }, "target": { "title": "微信", "process": "Weixin" } } }
```

失败响应：

```json
{ "id": "12", "ok": false, "error": { "message": "no window matches title='xxx'", "type": "RuntimeException", "detail": "..." } }
```

可用 `cmd`：`ping`、`status`、`screenshot`、`ocr`、`mouse`、`keyboard`、`windows`、`uia`、`clipboard`、`wait`、`pixel`、`shutdown`。

日志位置：

```
%TEMP%\dsh-desktop-control\agent.log                    每次请求一行（时间、命令、成功/失败、耗时）
%TEMP%\dsh-desktop-control\shots\*.png                  截图
%TEMP%\dsh-desktop-control\agent-*.ready.json           启动握手文件（正常情况下会被删除）
```
